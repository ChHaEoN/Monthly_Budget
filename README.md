# Monthly Budget｜每月開銷

個人用的記帳網頁：匯入 **DKB**、**VISA Amazon**、**AMEX** 的每月帳單（CSV、Excel、PDF），自動分類並計算每個月的**實際開銷**。

純靜態網頁，沒有後端。所有資料只存在瀏覽器的 `localStorage`，不會上傳到任何地方。

## 使用方式

```bash
npm start
```

然後開啟 <http://localhost:8000>。（因為使用 ES modules，不能直接雙擊 `index.html` 開啟；也可以部署到任何靜態主機。）

1. 從各家網銀下載帳單（CSV、Excel `.xlsx` 或 PDF），拖進頁面。
2. 匯入預覽會自動辨識來源、欄位與正負號，確認後匯入。
3. 在「總覽」查看當月實際開銷、分類佔比與近 12 個月趨勢。
4. 在「交易明細」上方的「快速分類」替未分類的商家選分類：一次歸類同商家的所有交易並存成規則。

## 支援的檔案格式

- **CSV**：最可靠，建議優先使用。
- **Excel (.xlsx)**：讀取第一張工作表，之後與 CSV 相同。不支援舊版 `.xls`。
- **PDF**：在瀏覽器內用 pdf.js 擷取文字，把「日期 … 說明 … 金額」的列還原成交易；匯入前一律先顯示預覽讓你確認。
  - 銀行對帳單：依負號、`S`/`H` 或借方／貸方欄位判斷收支。
  - 信用卡帳單：沒有標記的金額視為消費，帶 `CR`、`+`、`-` 的視為退款或繳款。
  - 掃描成圖片的 PDF、有密碼保護的 PDF 無法讀取。
- **同一期帳單請只匯入一種格式**：不同格式的交易說明文字不同，無法互相去重，會重複計算。

## 自動匯入資料夾

在「匯入與備份」選擇一個存放帳單檔案的資料夾（只需授權一次）。之後每次開啟或切回頁面時會自動掃描：

- 新的 CSV／Excel 會自動匯入；來源與欄位都能辨識的直接匯入，無法辨識的才會跳出預覽詢問。
- PDF 一律先跳出預覽確認；找不到交易明細的 PDF（與帳單無關的文件）會直接略過。
- 已處理過的檔案（以路徑、大小、修改時間判斷）不會重讀；就算重讀，交易也會被去重略過。
- 網頁只讀取、不會修改或刪除資料夾裡的檔案。
- 需要桌面版 Chrome 或 Edge（File System Access API）。瀏覽器若要求重新授權，頁面上方會出現提示。
- Amazon Visa 的檔案是靠檔名辨識，檔名需包含 `amazon`、`zinia` 或 `visa`。

## 「實際開銷」怎麼算

- 支出類交易的淨額；退款（正數）會抵減開銷。
- **信用卡繳款不重複計算**：DKB 扣繳 AMEX / Amazon Visa 帳單、以及信用卡端收到的繳款，都歸入「內部轉帳（不計入）」，消費只在信用卡明細中算一次。
- 儲蓄投資（如 Trade Republic、Sparplan）不計入開銷。
- 月份以交易日期歸屬（信用卡優先採用消費日而非入帳日）。
- DKB 尚未入帳 (Vorgemerkt) 的交易會略過，待入帳後再匯入。

## 其他

- **去重**：重複匯入同一份、或期間重疊的帳單不會重複計算。
- **規則**：關鍵字比對交易說明（不分大小寫、需位於單字開頭）。自訂規則優先於內建規則；手動改過的分類不會被覆蓋。
- **拆分交易**：在「交易明細」按「拆分」，可以把一筆交易拆成多個部分、各自歸類（例如一筆轉入同時包含收入與內部轉帳）。拆分記在原交易上，重新匯入同一份帳單不會重複、也不會被還原；規則變動也不會動到拆分過的交易。
- **個人規則**：你常去的商家請用「快速分類」或「我的規則」設定，它們只存在瀏覽器裡，不會進入公開的程式碼。可在「分類規則」匯出成 `.json`，拖進匯入區即可在另一台裝置匯入。
- **備份**：「匯入與備份」可匯出完整 JSON 備份，拖回頁面即可還原。清除瀏覽器資料會刪除所有紀錄，請定期備份。
- **格式不合時**：匯入預覽中可手動指定日期／金額／說明欄位與正負號。

## 開發

```bash
npm test
```

- `js/parse.js` CSV 解析與來源辨識
- `js/categorize.js` 分類與規則
- `js/store.js` 儲存、去重、月結計算
- `js/xlsx.js` Excel 讀取
- `js/pdf-text.js`、`js/pdf.js` PDF 帳單解析
- `js/folder.js` 自動匯入資料夾
- `vendor/pdfjs/` pdf.js（Apache-2.0）
- `js/app.js` 介面
- `test/samples/` 虛構的範例帳單
